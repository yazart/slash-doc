# Slash Doc

Slash Doc — расширение для Visual Studio Code, предназначенное для создания и публикации проектной и технической документации. Документы редактируются в собственном блочном редакторе `<slash-doc-editor>` и хранятся в рабочей папке проекта в формате YAML.

## Возможности

- древовидная структура страниц с переименованием, вложенностью и drag-and-drop;
- полнотекстовый поиск по документации;
- импорт HTML и Markdown, а также массовый импорт MkDocs-проектов из ZIP с сохранением `nav` или структуры каталогов;
- экспорт отдельных страниц в HTML и Markdown;
- сборка статического HTML-сайта с меню, поиском, внутренними ссылками и переключателем светлой/тёмной темы;
- внутренние ссылки между страницами и внешние ссылки, открывающиеся в новой вкладке;
- форматирование текста, таблицы в стиле Confluence, блоки кода и diff с подсветкой синтаксиса;
- Mermaid, Flow Designer, Network Canvas, BPMN Modeler и BPMN Preview;
- аннотирование изображений;
- описание API-эндпоинтов с примерами запросов и моделями TypeScript;
- доска задач в стиле Trello;
- обработка локальных CSV и JSON-файлов пользовательским JavaScript;
- MkDocs-совместимые примечания (`admonition`), вкладки контента, раскрываемые блоки и многоуровневые чеклисты с Markdown-содержимым;
- подключаемые аддоны с совместимым с Editor.js API и локальные HTTP API-модули;
- локальный MCP-сервер для чтения, поиска, изменения и сборки документации внешними AI-клиентами.

## Требования

- Visual Studio Code 1.90 или новее;
- Node.js 20.19 или новее и npm для разработки, тестирования и сборки расширения;
- открытая рабочая папка VS Code для хранения документации.

## Использование

1. Откройте папку проекта в VS Code.
2. Откройте представление **Slash Doc** в Activity Bar.
3. Создайте страницу или выполните команду **Slash Doc: Открыть редактор**.
4. Добавляйте блоки через Ctrl/⌘+I или клик по пустому месту. Изменения сохраняются автоматически.
5. Используйте иконочные кнопки в панели страниц для импорта документа или сборки HTML-документации.

Для переноса существующего MkDocs-проекта нажмите кнопку импорта и выберите ZIP-архив. Импортёр ищет
`mkdocs.yml`/`mkdocs.yaml`, учитывает `docs_dir` и `nav`, переносит все Markdown-страницы в штатные
`content.yaml` и сохраняет вложенность меню. Если конфигурации или `nav` нет, иерархия строится по
каталогам; `index.md`/`README.md` становится страницей соответствующего раздела. Локальные изображения
из Markdown извлекаются из архива и сохраняются как ресурсы рядом с YAML-файлом страницы.

### Chrome-расширение для GitLab

В проект входит отдельное расширение Manifest V3 для Chrome 111 и новее. Оно автоматически
открывает визуальный редактор Slash Doc на страницах GitLab **Edit single file**, если URL имеет
вид `https://<gitlab>/<project>/-/edit/<branch>/.slash-doc/docs/pages/<page-id>/content.yaml`.
Поддерживаются GitLab.com и собственные GitLab-инсталляции. На остальных страницах интерфейс
не добавляется.

Соберите расширение:

```sh
npm run compile:chrome
```

В Chrome откройте `chrome://extensions`, включите «Режим разработчика», нажмите «Загрузить
распакованное расширение» и выберите `dist/chrome-extension`. После установки обновите открытую
страницу GitLab: мост должен перехватить событие инициализации его редактора.

Визуальный редактор использует штатные виджеты Slash Doc. Кнопка «Стандартный редактор GitLab»
переключает режим; при возврате в визуальный режим YAML читается заново из модели GitLab.
Изменения через секунду или по кнопке «Применить в GitLab» передаются в модель Monaco.
Перед переключением, открытием диалога коммита и отправкой формы последние изменения
синхронизируются. Коммит выполняется штатной кнопкой **Commit changes** GitLab; расширение
самостоятельно не отправляет коммиты и не требует токена доступа.

Существующие ресурсы из соседних файлов загружаются из той же ветки репозитория. Неизменённые
ресурсы сохраняют ссылки `./image-…`, `./svg-…` и `./bpmn-…`. Новые или изменённые ресурсы
встраиваются в YAML, поскольку режим single-file сохраняет один файл. Поиск пользователей
использует GitLab `/api/v4/users`; список страниц для внутренних ссылок читается из `menu.json`.
Локальное выполнение JavaScript в обработчике файлов и пользовательские модули VS Code требуют
расширения VS Code и недоступны в браузере. Если чтение YAML или ресурса завершается ошибкой,
стандартный редактор остаётся доступным.

`npm run test:chrome` собирает Chrome-расширение и проверяет редактор в браузере на локальной
GitLab-подобной странице, включая CSP Manifest V3, переключение режимов и синхронизацию перед
коммитом. Путь к Chrome можно задать переменной `SLASH_DOC_CHROME_PATH`.

### Хранение данных

Документация находится внутри рабочей папки:

```text
.slash-doc/
├── sdsettings.json
└── docs/
    ├── menu.json
    └── pages/
        └── <page-id>/
            ├── content.yaml
            ├── image-<hash>.<ext>
            ├── svg-<hash>.svg
            └── bpmn-<hash>.bpmn
```

`content.yaml` содержит полное состояние блочного редактора. Base64-изображения, SVG и BPMN XML автоматически
выносятся в отдельные файлы со стабильными hash-именами и восстанавливаются при открытии страницы.
Старый `content.json` читается автоматически и удаляется только после успешного сохранения YAML и ресурсов.

Загруженные файлы блока обработки данных сохраняются рядом с соответствующей страницей. Глобальные пользовательские аддоны находятся в `addons/`, а HTTP API-модули — в `api/` рядом с расширением.

> Пользовательский JavaScript блока обработки файлов выполняется локально с доступом к файлам блока. Запускайте только доверенный код.

### BPMN

- **BPMN Modeler** создаёт и редактирует BPMN 2.0-диаграммы с помощью `bpmn-js 9.0.0`.
- **BPMN Preview** принимает BPMN XML из файла, drag-and-drop или текстового поля.
- XML и SVG сохраняются отдельными файлами рядом со страницей; при HTML-экспорте оба блока становятся статическим SVG.
- Водяной знак bpmn.io является обязательной частью `bpmn-js 9.0.0` и должен оставаться видимым.

### Автономная сборка документации

HTML-сайт можно собрать без VS Code и без запуска расширения. После `npm run compile` используйте
переносимый Node.js-файл `dist/slash-doc-compile.js`:

```sh
node dist/slash-doc-compile.js /path/to/project
node dist/slash-doc-compile.js /path/to/project --output /path/to/site
node dist/slash-doc-compile.js /path/to/project --repository https://gitlab.example/group/project
node dist/slash-doc-compile.js /path/to/project --repository https://gitlab.example/group/project --default-branch master
node dist/slash-doc-compile.js /path/to/project --format md --output /path/to/markdown
```

По умолчанию HTML сохраняется в `<проект>/slash-doc-site`. В режиме `--format md` результат
сохраняется в `<проект>/slash-doc-markdown`: в корне создаётся `README.md`, а страницы получают
иерархические пути `<Название страницы>/<Название страницы>.md`, повторяющие меню. Имя корневого
файла можно изменить в настройке «Корневой Markdown-файл». Утилита читает
`.slash-doc/docs/menu.json`, содержимое страниц и `.slash-doc/sdsettings.json`. Настройка
«Сохранять файлы документа отдельно» действует для HTML и Markdown: если она выключена, ресурсы
встраиваются в документ; если включена — сохраняются рядом с экспортируемой страницей. В собранном
HTML-сайте переключатель в заголовке меню меняет светлую и тёмную тему. Выбор сохраняется в
`localStorage` браузера и применяется также к страницам внутри iframe.

В настройках экспорта доступны «Кнопка „Скопировать HTML“» (`showCopyHtmlButton`,
по умолчанию включена) и «Переходы „Назад / Вперёд“ в HTML» (`showPageNavigation`,
по умолчанию выключены). Переходы внизу страницы следуют порядку меню, включая
вложенные документы. Логотип с названием проекта ведёт на `/`. Кнопка слева вверху
скрывает и показывает навигацию; выбор сохраняется в браузере.

Настройка «Ссылка на репозиторий в HTML» (`exportOptions.showRepositoryLink`)
по умолчанию выключена. Если включить её и задать URL репозитория, под названием
документации в сайдбаре появится ссылка «Репозиторий», открывающаяся в новой вкладке.
При сборке через CLI URL также можно задать параметром `--repository`.

В настройках экспорта можно загрузить собственный favicon (PNG, JPEG, GIF, WebP, SVG
или ICO), увидеть предпросмотр и сбросить его к стандартному значку Slash Doc.
Изображение хранится в `exportOptions.favicon` и встраивается в главную HTML-страницу
и каждый документ, включая сборку с извлечением файлов.

При копировании HTML ссылки на извлечённые картинки и SVG заменяются на Base64 data URL.
Если кнопка копирования включена, сборка встраивает данные для буфера обмена в страницу,
поэтому копирование работает и при открытии HTML с диска. Сам документ продолжает
показывать извлечённые файлы; в скопированном HTML нет кнопки копирования и переходов.

В HTML под первым заголовком страницы выводятся создатель файла из первого Git-коммита,
дата и автор последнего изменения. При переименовании файла сохраняется его Git-история.
Для ещё не закоммиченного нового файла используется имя текущего Git-пользователя. Параметр
`--repository` задаёт HTTP(S) URL GitLab-проекта; компилятор определяет текущую ветку и формирует
ссылку вида `<repository>/-/edit/<branch>/.slash-doc/docs/pages/<page-id>/content.yaml`. Для сборки из
расширения тот же URL задаётся в настройке «GitLab-репозиторий». В URL используется только имя
текущей ветки, но не хеш коммита. Если текущая ветка недоступна (например, при detached HEAD),
используется настройка «Ветка по умолчанию» или параметр `--default-branch`; начальное значение —
`master`. Если файл изменён, но ещё не
закоммичен, используются его дата изменения и имя текущего Git-пользователя.

Для экспорта пользовательских аддонов передайте каталог с их модулями:

```sh
node dist/slash-doc-compile.js /path/to/project --addons /path/to/addons
```

Файл компилятора можно скопировать отдельно от расширения на машину с Node.js 20.19 или новее.
После `npm link` та же команда доступна как `slash-doc-compile`.

### MCP-сервер

После сборки запускается отдельный stdio-сервер:

```sh
node dist/slash-doc-mcp.js /path/to/project
# или после npm link
slash-doc-mcp --project /path/to/project
```

Пример конфигурации MCP-клиента:

```json
{
  "mcpServers": {
    "slash-doc": {
      "command": "node",
      "args": ["/path/to/slash-doc/dist/slash-doc-mcp.js", "/path/to/documented-project"]
    }
  }
}
```

Путь также можно задать переменной `SLASH_DOC_PROJECT_ROOT`. Сервер публикует дерево и страницы как
MCP resources и предоставляет tools `list_pages`, `read_page`, `search_pages`, `create_page`,
`replace_page`, `append_blocks`, `rename_page`, `move_page`, `delete_page` и
`compile_documentation`. Изменения записываются в штатный формат `content.yaml`; изображения, SVG и
BPMN остаются отдельными hash-файлами рядом со страницей.

## Разработка

```sh
npm install
npm run compile
```

Сборка выполняется Vite и формирует в `dist/` точки входа для extension host, основного webview,
sidebar, обработчика файлов, автономного компилятора и MCP-сервера. Откройте проект в VS Code, нажмите
`F5` и запустите расширение в Extension Development Host.

Основные команды:

## CHANGELOG и релизы

CHANGELOG формируется из [Conventional Commits](https://www.conventionalcommits.org/):

```text
feat: добавить новый виджет
fix: исправить импорт таблицы
docs: обновить README
chore: обновить зависимости
```

Для ручной генерации выполните:

```sh
npm run changelog
```

При выполнении `npm version patch|minor|major` CHANGELOG пересоздаётся автоматически и добавляется в Git index вместе с новой версией.

### Блочный редактор

Редактор реализован как web component `slash-doc-editor` без зависимости от Editor.js.
Сохранён формат `{ blocks: [{ id, type, data, tunes? }] }`, методы `isReady`, `save()`,
`render()`, `destroy()`, `blocks`, `caret`, `readOnly`, а также контракт аддонов
`constructor({ data, api, config, readOnly, block })`, `render()`, `save()` и `destroy()`.
Неизвестные или отключённые блоки сохраняются вместе с исходными данными.

Нажмите на ручку ⋮⋮ в заголовке блока, чтобы выделить его. Shift выделяет диапазон,
Ctrl/⌘ добавляет отдельные блоки. Ctrl/⌘+C, X и V копируют, вырезают и вставляют
выделенные блоки; кнопка копирования доступна в заголовке блока. Вставка добавляет
блоки после выделения или текущего блока, сохраняет их порядок и создаёт новые ID.
Escape снимает выделение, Delete удаляет выбранные блоки. Ручка также позволяет
перемещать блоки перетаскиванием: показывается весь блок и место вставки. Рамок у блоков
и ручек нет. Обычное выделение текста сохраняет обычное копирование.

Блоки также можно выделять рамкой: нажмите на свободном месте редактора или между
блоками и протяните мышью. Блоки, пересекающие рамку, подсвечиваются сразу.
Ctrl/⌘ или Shift добавляет их к текущему выделению, Escape отменяет протягивание.
У края области просмотра редактор прокручивается; выделенную группу можно копировать,
удалять и перемещать теми же кнопками и сочетаниями клавиш.

После каждого блока остаётся пустое место: клик создаёт здесь текстовый блок.
Ctrl/⌘+I или Insert открывает меню добавления после текущего блока.
Новая таблица содержит две строки и два столбца, включая создание через смену типа блока.
Клик по пустому месту редактора также создаёт текстовый блок. Нажатие на название
блока или ПКМ по ручке открывает меню смены типа; при преобразовании сохраняется ID блока.

Выбор языка кода, действия BPMN и настройки MkDocs находятся в общей шапке блока.
Сепаратор отделяет их от стандартных кнопок перемещения, копирования и удаления.
Повторяющиеся заголовки внутри тела кода, Diff, BPMN и MkDocs убраны.

Меню добавления и смены типа упорядочены от простых блоков к специализированным:
текст, цитата, списки, таблицы и изображения, затем MkDocs-блоки, код и диаграммы,
специализированные инструменты и пользовательские аддоны. BPMN Preview и Modeler
находятся в конце.

Блок «Сетка MkDocs» поддерживает карточки и обычную адаптивную сетку по примеру
[Material for MkDocs](https://squidfunk.github.io/mkdocs-material/reference/grids/).
В шапке можно добавлять и удалять элементы, выбирать активный элемент и переключать
оформление карточек. Внутри элементов доступны текст, заголовки, списки, разделители
и ссылки, включая внутренние ссылки на страницы. При узкой ширине элементы
располагаются друг под другом. HTML-экспорт сохраняет адаптивность и тему,
Markdown-экспорт использует контейнер `grid` и элементы `card`; для Material
нужны расширения `attr_list` и `md_in_html`. Импорт поддерживает сохранённые сетки
и синтаксис карточек Material, включая списки и HTML-контейнеры.

Меню типов блоков содержит иконки. Абзац и заголовок объединены в блок «Текст»:
выберите «Абзац» или уровень H1–H6 в его заголовке. Старые блоки заголовков сохраняют
уровень и содержимое. Блок «Цитата» поддерживает форматирование, ссылки и списки,
а также импорт и экспорт HTML и Markdown. Ctrl/⌘+↑ и Ctrl/⌘+↓ перемещают текущий
блок или выделенную группу на одну позицию, сохраняя порядок и положение курсора.

В многоуровневом списке Backspace на пустом пункте удаляет этот пункт и переводит
курсор в соседний. Дочерние пункты сохраняются и поднимаются на один уровень.
Последний пустой пункт превращается в обычный текстовый блок.

Ctrl/⌘+V с изображением в буфере автоматически добавляет блок «Изображение» после
текущего блока или выделенной группы. Несколько изображений вставляются по порядку;
картинки сохраняются вместе с документом. В редакторе аннотаций вставка обновляет
его изображение.

В пустой блок «Изображение» можно перетащить файл или нажать на область загрузки,
чтобы открыть выбор файла. Клик по изображению и кнопка «Заменить изображение»
в заголовке также открывают выбор файла. Настройки рамки, фона и растягивания

Цвета Mermaid берутся из текущей темы, включая заливку узлов и текст. При смене темы
диаграммы обновляются автоматически, и SVG сохраняется с актуальными цветами.

Выделите текст внутри абзаца, ячейки таблицы или MkDocs-блока, чтобы создать список,
добавить ссылку или применить форматирование. MkDocs-блоки используют contenteditable,
а параметры и названия находятся в заголовке. Старое Markdown-содержимое автоматически
отображается в редактируемом виде; ссылки и списки сохраняются при экспорте.

В inline-панели «Фон выделения» задаёт цвет фона выбранного текста, а «Убрать фон
выделения» снимает его. Inline-панель появляется только при выделении текста.
В заголовке таблицы «Фон ячеек» закрашивает текущую ячейку или выбранную
группу ячеек, включая пустые и заголовочные ячейки. Подсветка выделения имеет
непрозрачность 10%, сохраняя читаемость текста и видимость собственной заливки.
«Убрать фон ячеек» снимает собственный цвет; ранее сохранённые фоны строк продолжают
отображаться. Цвета сохраняются при добавлении и удалении строк и столбцов, а также
при экспорте в HTML и Markdown; цветные таблицы в Markdown выводятся как HTML.
Заголовок таблицы также содержит кнопки добавления и удаления текущей строки или
столбца и вставки из буфера обмена. Строки и столбцы добавляются после текущей ячейки.
«Цвет текста» и «Фон выделения» доступны во всех полях rich-text редактирования
`contenteditable`, включая пользовательские блоки и их Shadow DOM.
Палитра и другие поля inline-панели сохраняют выбранный фрагмент текста при смене
фокуса. Панель форматирования закрывается после сброса выделения.

В таблице Ctrl/⌘+A выделяет текст только текущей ячейки. Ctrl/⌘+V вставляет текст
в позицию курсора или заменяет выделенное содержимое; таблица из буфера вставляется
как диапазон ячеек. После такой вставки фокус остаётся в таблице для дальнейшего
редактирования и повторной вставки.
